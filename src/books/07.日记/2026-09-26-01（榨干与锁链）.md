## 1.锁链形态
```python

    if 给:   被榨干 → 恨
    if 不给: 不孝 → 罪咎
```

**健壮性设计说明：**

* **去分支化**：旧代码的死因是两个分支都通向罪咎。新代码删掉 `给/不给` 判断——行为成为输出，不再是输入。
* **无状态**：不维护"我欠多少／我付了多少"账本。账本就是罪咎固件的持久化存储，删表即卸载。
* **故障语义反转**：失手（又内疚了、又吵了）不抛异常、不记日志、不自罚——只是重连顾问（W-95.8：错误有待修正，如此而已）。
* **单一度量**：`peace_check()` 是唯一的健康端点。平安=系统正常；不平安=该重连。
