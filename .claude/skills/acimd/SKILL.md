# acimd：对话灵感存档

把（通常是和 hermes 的）杂乱对话整理成书集文章，写入：
- **日记** `/home/yg/__work/acim-web/src/books/07.日记/` — 感悟、灵感、杂记、非问答式内容
- **问答** `/home/yg/__work/acim-web/src/books/06.问答/` — 一问一答，正文含 `## 问：` 结构

## 两阶段协议（硬性规定）

本技能在任何情况下都是**两轮对话**，不存在一轮完成：

- **第一轮（草稿轮）**：用户说"存档/存到日记/写入日记/保存这段"等任何存档意图时，本轮**只做**步骤 1–3，然后输出草稿预览并停止。预览格式：
  ```
  【草稿待确认】
  目录：07.日记
  文件：2026-10-02-04（标题）.md
  ─────
  <正文全文>
  ─────
  回复"确认"写入；或直接说改哪里。
  ```
- **第二轮（写入轮）**：只有用户在草稿预览之后的消息里明确说"确认/可以/写吧/OK"等，才执行写入。

**"写入日记""直接存"这类祈使句不是确认**——它们只是触发草稿轮。用户的确认必须出现在看到草稿之后。唯一例外：用户在同一条消息里已经看过并逐字给出了完整正文和标题（视为预确认），此时仍需先跑脚本生成文件名并回显，再写入。

## 流程

### 1. 定目录
看内容形态：有明确"问：…答：…"结构 → wenda；其余 → riji。拿不准就问用户。

### 2. 提炼标题和正文
- **标题：意义优先，不是主题优先**。标题取自正文的**核心结论/洞察/金句**，让读者只看标题就知道"这篇主张什么"，而不是"这篇关于什么"
  - ✅ 好标题（观点/结论）：「要开心还是要宽恕」「不顾你死活的向爱求助」「无存量服务协议」「懂与不懂谁更合适」
  - ❌ 坏标题（话题/情绪/氛围词）：「悲壮」「阴天」「关于宽恕的思考」
  - 提炼顺序：**先写正文 → 从正文里找结论句或最有力的那句 → 压缩成标题**。找不到结论句说明正文还没提炼到位，回去改正文
  - 拿不准时在草稿里给 2–3 个候选标题让用户挑，不要自作主张定一个平庸的
  - 硬性约束：不含日期、不含序号、不含非法字符（`\/:*?"<>|`）
- **正文**：markdown。整理而非照搬——去寒暄、合并重复、保留金句和判别器式结论。问答体用 `## 问：xxx` 分节（参考 011.药物与符咒.md）
- 日记正文一级标题可用 `# 标题：副题` 形式（参考 2026-10-02-03）

### 3. 生成文件名（必须用脚本，不要自己编文件名）
```bash
python3 /home/yg/__work/acim-web/.claude/skills/acimd/scripts/gen_filename.py riji "标题" --full
python3 /home/yg/__work/acim-web/.claude/skills/acimd/scripts/gen_filename.py wenda "标题" --full
```
输出即目标绝对路径。规则：
- 日记：`YYYY-MM-DD（标题）.md`；当天已有文件则 `-NN` 递增（当天首个无后缀文件视为 01）
- 问答：`NNN.标题.md`，取现有最大序号+1

注意：若日记当天已有无后缀文件且脚本给出了 `-02`，应提醒用户是否把旧文件改名为 `-01` 保持序列一致。

### 4. 输出草稿预览并停止
按上方"两阶段协议"的格式输出草稿，**本轮到此结束，不调用 Write**。用户改标题或正文后，**重新跑脚本**生成文件名（序号可能不变，但必须重跑以防标题变了），再出新一轮草稿。

### 5. 写入（仅在收到确认后）
用 Write 写入脚本输出的路径。

**不要**手动更新两个目录下的 `index.md`——`scripts/build.mjs`（gen-index.mjs）会自动重建目录和搜索索引。写完后提醒用户：需要发布时跑构建/提交。

## 禁区
- 禁止自己拼文件名（日期错误、序号冲突都出过）
- **禁止在草稿轮写入文件**——"写入日记"等指令只触发草稿，确认必须是用户看到草稿后的独立一句话
- 禁止改动其他已有文件（改名旧日记文件前必须先问）
